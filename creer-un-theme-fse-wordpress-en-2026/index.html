    Un guide complet pour maîtriser le Full Site Editing et devenir un vrai thémeur moderne

    Commencer la lecture

    Qu'est-ce que le Full Site Editing ?

    Pendant des années, WordPress proposait deux approches pour créer des sites :

    Les thèmes classiques

    • Vous éditiez le contenu uniquement
    • Le design était figé dans le code PHP
    • Modifier l'en-tête ou le pied = code + FTP
    • Peu de flexibilité pour le client

    Le Full Site Editing (FSE)

    • Vous contrôlez 100% du site via l'interface
    • Pas de code pour modifier un design
    • Patterns et templates réutilisables
    • Variations de thème (light/dark) en 2 clics

    Le FSE, c'est Wordpress qui enfin comprend qu'un designer ne doit pas savoir coder PHP.

    « Le Full Site Editing transforme WordPress : de plateforme de contenu à plateforme de design sans code. Que vous soyez freelance ou agence, maîtriser FSE, c'est déverrouiller des projets plus lucratifs et clients plus satisfaits. »

    L'architecture d'un thème FSE

    Un thème FSE n'est pas complexe, mais bien structuré. Voici l'arborescence minimale :

    mon-theme-fse/
├── style.css              ← Header du thème
├── theme.json             ← Cœur du design (tokens, couleurs, polices)
├── functions.php          ← Hooks et enregistrements
├── templates/             ← Les pages (index, single, page, archive…)
│   ├── index.html
│   ├── single.html
│   ├── page.html
│   └── archive.html
├── parts/                 ← Sections réutilisables (header, footer, sidebar)
│   ├── header.html
│   ├── footer.html
│   └── sidebar.html
├── patterns/              ← Patterns (hero, testimonial, CTA…)
│   ├── hero.php
│   └── testimonial.php
├── assets/
│   ├── images/
│   ├── fonts/
│   └── css/
└── styles/                ← Variations de thème (light, dark…)
    ├── light/theme.json
    └── dark/theme.json

    Note : Contrairement aux thèmes classiques, pas besoin de templates PHP complexes. FSE utilise des fichiers HTML/XML légers.

    theme.json — Le cœur du design

    theme.json est le fichier le plus important d'un thème FSE. C'est lui qui définit tous les tokens de design : couleurs, polices, espacements, et styles globaux.

    Pourquoi theme.json et pas du CSS classique ?

    1. Design tokens centralisés : Une couleur définie une fois, utilisée partout
    2. CSS auto-générées : WordPress crée les variables CSS pour vous (ex: var(--wp--preset--color--primary))
    3. Site Editor compatible : Les réglages de theme.json apparaissent dans l'interface d'édition
    4. Responsive by default : Fluid typography et spacing automatiques

    Exemple minimal de theme.json

    {
  "$schema": "https://schemas.wp.org/trunk/theme.json",
  "version": 3,
  "settings": {
    "color": {
      "palette": [
        {
          "name": "Primary",
          "slug": "primary",
          "color": "#0073aa"
        },
        {
          "name": "Secondary",
          "slug": "secondary",
          "color": "#005a87"
        },
        {
          "name": "Accent",
          "slug": "accent",
          "color": "#f70000"
        }
      ]
    },
    "typography": {
      "fontFamilies": [
        {
          "fontFamily": "\"Inter\", sans-serif",
          "slug": "system",
          "name": "System Font"
        },
        {
          "fontFamily": "\"Playfair Display\", serif",
          "slug": "serif",
          "name": "Serif"
        }
      ],
      "fontSizes": [
        {
          "name": "Small",
          "slug": "small",
          "size": "14px"
        },
        {
          "name": "Normal",
          "slug": "normal",
          "size": "16px"
        },
        {
          "name": "Large",
          "slug": "large",
          "size": "20px"
        }
      ]
    },
    "spacing": {
      "spacingScale": {
        "steps": 0,
        "mediumPoint": 0
      }
    },
    "layout": {
      "contentSize": "800px",
      "wideSize": "1200px"
    }
  },
  "styles": {
    "color": {
      "background": "#ffffff",
      "text": "#333333"
    },
    "typography": {
      "fontFamily": "var(--wp--preset--font-family--system)",
      "fontSize": "var(--wp--preset--font-size--normal)",
      "lineHeight": 1.6
    }
  }
}

    Ce qu'il faut retenir :

    • settings = Configure ce que les utilisateurs peuvent personnaliser
    • styles = Définit les styles par défaut
    • Presets = Palettes prédéfinies (couleurs, polices, tailles)
    • Variables CSS = Créées auto par WordPress depuis les presets

    Templates — Les pages de votre site

    Les templates sont des fichiers HTML/XML qui définissent la structure des différents types de pages : accueil, articles, pages statiques, archives…

    Les 5 templates obligatoires

    Exemple : un template simple

    Voici le contenu du fichier single.html :

    <!-- wp:template-part {"slug":"header"} /-->

<main>
  <!-- wp:group {"align":"wide"} -->
  <div class="wp-block-group">
    <!-- wp:post-title /-->
    <!-- wp:post-featured-image /-->
    <!-- wp:post-content /-->
  </div>
  <!-- /wp:group -->
</main>

<!-- wp:template-part {"slug":"footer"} /-->

    Décortiquons ce template :

    • <!-- wp:template-part {"slug":"header"} /--> = Inclut le bloc "header" depuis /parts/header.html
    • <!-- wp:post-title /--> = Affiche le titre de l'article
    • <!-- wp:post-featured-image /--> = Affiche l'image à la une
    • <!-- wp:post-content /--> = Affiche le contenu de l'article

    Aucun PHP, aucune requête SQL. Juste des blocs déclaratifs. C'est magique ! 🎉

    Patterns et Parts — Les briques réutilisables

    FSE vous permet de créer des briques réutilisables : les patterns et les template-parts.

    📦 Template-Parts

    Fichier : /parts/

    Sections globales du site :

    • Header
    • Footer
    • Sidebar
    • Navigation

    Utilisés dans les templates.

    ✨ Patterns

    Fichier : /patterns/

    Composants réutilisables :

    • Hero (bannière)
    • Testimonial (avis)
    • CTA (call-to-action)
    • Features (3 colonnes)

    Insérés dans l'éditeur de contenu.

    Exemple : Créer un pattern Hero

    Fichier /patterns/hero.php :

    <?php
/**
 * Title: Hero Banner
 * Slug: my-theme/hero
 * Categories: featured
 * Description: Un hero banner moderne
 */
?>

<!-- wp:group {
  "align":"full",
  "layout":{"type":"constrained"},
  "backgroundColor":"primary"
} -->
<div class="wp-block-group">
  <!-- wp:heading {"textAlign":"center","textColor":"base"} -->
  <h2 class="wp-block-heading has-text-align-center">Bienvenue sur mon site</h2>
  <!-- /wp:heading -->
  
  <!-- wp:paragraph {"align":"center","textColor":"base"} -->
  <p class="has-text-align-center">Découvrez nos services exceptionnels</p>
  <!-- /wp:paragraph -->
  
  <!-- wp:buttons {"justify":"center"} -->
  <div class="wp-block-buttons">
    <!-- wp:button -->
    <div class="wp-block-button">
      <a class="wp-block-button__link">Commencer</a>
    </div>
    <!-- /wp:button -->
  </div>
  <!-- /wp:buttons -->
</div>
<!-- /wp:group -->

    Puis enregistrez ce pattern dans functions.php :

    // Dans functions.php
function mon_theme_register_patterns() {
    // Le fichier PHP est auto-détecté par WordPress
    // si on place les patterns dans /patterns/ et qu'on active le thème
}
// Les patterns PHP sont auto-enregistrés en WordPress 6.5+

    Variations de thème — Light, Dark et autres

    Une des plus grandes forces de FSE : créer plusieurs variations visuelles du même thème en quelques minutes.

    Structure : Un dossier /styles/ dans votre thème, avec un sous-dossier par variation.

    styles/
├── light/
│   ├── theme.json          ← Surcharge les couleurs pour le mode clair
│   └── screenshot.png      ← Aperçu du thème clair
├── dark/
│   ├── theme.json          ← Surcharge pour mode sombre
│   └── screenshot.png
└── neon/                   ← Votre variation custom
    ├── theme.json
    └── screenshot.png

    Exemple : theme.json pour le mode Dark

    Fichier styles/dark/theme.json :

    {
  "version": 3,
  "title": "Dark Mode",
  "settings": {
    "color": {
      "palette": [
        {
          "name": "Background",
          "slug": "background",
          "color": "#1a1a1a"
        },
        {
          "name": "Text",
          "slug": "text",
          "color": "#ffffff"
        },
        {
          "name": "Primary",
          "slug": "primary",
          "color": "#64b5f6"
        }
      ]
    }
  },
  "styles": {
    "color": {
      "background": "#1a1a1a",
      "text": "#ffffff"
    }
  }
}

    WordPress détecte automatiquement les variations dans /styles/ et les propose dans le Site Editor. Pas de code, pas d'actions PHP. Magique. ✨

    Polices et performance

    Les polices de caractères jouent un rôle crucial dans l'identité visuelle. FSE vous permet de les gérer directement dans theme.json.

    Deux approches

    Configuration dans theme.json

    functions.php essentiels

    Même en FSE, un functions.php minimaliste reste nécessaire pour :

    • Enregistrer les patterns
    • Ajouter les supports du thème
    • Charger les styles éditeur
    • Hooks personnalisés

    Exemple complet

    <?php
/**
 * Functions.php - Mon thème FSE
 */

// 1. Supports du thème
function mon_theme_setup() {
    add_theme_support( 'wp-block-styles' );
    add_theme_support( 'align-wide' );
    add_theme_support( 'responsive-embeds' );
}
add_action( 'after_setup_theme', 'mon_theme_setup' );

// 2. Enregistrement des patterns (optional, auto-détecté en 6.5+)
function mon_theme_register_patterns() {
    // Les patterns PHP dans /patterns/ 
    // sont auto-enregistrés
}
add_action( 'init', 'mon_theme_register_patterns' );

// 3. Style éditeur pour prévisualiser
function mon_theme_editor_styles() {
    add_editor_style( 'style.css' );
}
add_action( 'admin_init', 'mon_theme_editor_styles' );

    Note : Dans WordPress 6.5+, les patterns PHP sont auto-découverts. Pas besoin de les enregistrer ! 🎉

    Bonnes pratiques et checklist

    Avant de publier votre thème FSE :

    • ✅ style.css avec header complet (texte, version, auteur…)
    • ✅ theme.json avec version 3 et $schema
    • ✅ Dossiers templates/, parts/, patterns/ créés
    • ✅ Au moins les 5 templates obligatoires
    • ✅ Un screenshot.png pour l'aperçu (1200x900px)
    • ✅ Testé sur WordPress 6.8+
    • ✅ Polices optimisées (local préféré à Google)
    • ✅ Variations de thème (light/dark au minimum)
    • ✅ Code commenté et lisible
