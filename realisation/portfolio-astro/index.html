Ce portfolio en Astro

Mon portfolio, migré de WordPress vers Astro : un site statique publié sur GitHub Pages, un éditeur Gutenberg réutilisé hors de WordPress et des contenus versionnés dans Git.

  • astro
  • freelance
  • gutenberg

  • react
2026-10-04T10:00:00

Le site que vous lisez tournait sous WordPress. Je l’ai reconstruit avec Astro pour obtenir un site statique, rapide et gratuit à héberger, sans perdre le confort d’édition de Gutenberg.

  • Cadre : projet personnel, mené comme une mission client
  • Stack : Astro, React, TypeScript, Node (node:sqlite), éditeur de blocs WordPress
  • Hébergement : GitHub Pages, publication par une commande de déploiement
  • Code : github.com/waner1er/erwan-rivet

Contexte

Un portfolio n’a pas besoin d’un serveur PHP et d’une base MySQL en production. Je voulais un site statique, mais en gardant les contenus déjà écrits en blocs Gutenberg et la possibilité de les éditer visuellement.

Problématiques

  • Reprendre tout le contenu WordPress (pages, réalisations, articles, médias) et son rendu sans réécrire chaque page.
  • Garder un éditeur visuel sans faire tourner WordPress.
  • Publier sur GitHub Pages : pas de PHP, pas de base de données, un site servi dans un sous-dossier.
  • Préserver le référencement : sitemap, données structurées, URLs, performances.

Spécificités techniques

Les contenus versionnés dans Git

Pages, réalisations, projets, réglages et médias vivent dans des fichiers JSON du dépôt. Une base SQLite locale (le module natif node:sqlite) sert de cache et se resynchronise toute seule après un git pull.

Gutenberg hors de WordPress

Le back-office local embarque l’éditeur de blocs de WordPress (paquets @wordpress/* en React). Côté site, un moteur de rendu équivalent à render_block() transforme les blocs en HTML, y compris des blocs dynamiques maison (menu, recherche, réseaux sociaux).

Un thème découplé

Couleurs, typographies et espacements sont déclarés dans un theme.json compilé en variables CSS. Le thème peut changer sans toucher ni au contenu ni aux gabarits.

Export statique et SEO

Toutes les routes publiques sont pré-rendues en HTML, les URLs préfixées pour le sous-dossier GitHub Pages. Le build génère aussi le sitemap, le flux RSS, les données structurées JSON-LD, un llms.txt pour les moteurs IA et l’index de la recherche instantanée. Le formulaire de contact passe par un service externe.

Résultat

Un site sans serveur à maintenir, des pages servies en HTML statique et un historique complet des contenus dans Git. Cette refonte du front a d’ailleurs été faite directement dans le dépôt, sans passer par le back-office.
